Flexiv common-world TCP observations

observation_pose_frame: base (default) keeps the original RDK observations.
observation_pose_frame: world applies explicit left/right base poses to the
public left_ee_pose.* and right_ee_pose.* observations before dataset packing.
Positions remain in metres; rx/ry/rz remain rotation-vector components in radians.

Each base pose is T_world_base, encoded [x, y, z, qw, qx, qy, qz]. Both translation
and orientation are transformed: T_world_tcp = T_world_base * T_base_tcp.
The internal RDK pose caches and Cartesian servo targets remain in base frames.
The existing action mappings and the common multi-robot dataset schema are preserved.

deepcybo-5090 station convention (operator dimensions, 2026-10-20):
  Base centres are 0.32 m apart at the same height, 0.16 m on each side of origin.
  Origin: midpoint of the two base centres, at base height.
  +Y: toward the left base; +Z: up; +X: Y cross Z (right-handed).
  Left base position:  [0, +0.16, 0] m.
  Right base position: [0, -0.16, 0] m.
  RDK axes are treated as aligned with the workspace; mounting-yaw compensation
  and base-to-world rotation are both zero. The operator's forward-motion check
  found that the previous +/-45 degree action compensation made the left arm
  drift left and the right arm drift right, so that compensation was removed.
  The remaining common-frame extrinsic is the +/-0.16 m base-centre translation.
  This is a functional alignment check, not a new precision extrinsic calibration.

The workstation entry points use these repository configs through their existing paths.
Other installations must set their own measured base poses before enabling world mode.
Missing or invalid extrinsics fail before connecting hardware.

Same-side mapping for an operator behind the robots facing the workspace:
  Oculus right/up/back axes -> common-world left/up/back via
    C = [[0,0,-1],[-1,0,0],[0,1,0]].
  Thus operator forward/left/up maps to common-world +X/+Y/+Z.
  Both translation and axial rotation use the same proper rotation C (det=+1).
  The shared Oculus mapper outputs rotation as [rz,rx,ry], so the Flexiv config
  uses axis order [0,1,2] and signs [1,1,1,-1,-1,1] for BOTH hands to realize C.
  No extra X/Y exchange or opposite-hand horizontal signs remain.
  Base mounting yaw (zero on this workstation) is applied only afterward. Six-axis tests compose the base
  transforms back to the common world and check position and rotation on both arms.
  rx/ry/rz are rotation-vector components, not additive Euler RPY angles.
  The workstation zero-yaw setting follows the operator's axis-direction check;
  other installations still need their own measured base extrinsics.

Continuous gripper response:
  Historical Move-path tuning below is superseded on this station by the
  force_feedback controller described at the end of this document.
  Linear trigger response (gamma=1), with 2% endpoint deadzones.
  Command deadband is 0.2 mm. Intermediate aperture commands use a 0.05 m/s
  velocity cap and the latest target every 0.20 s. Full-open/full-close targets
  and direct startup/home moves retain the hardware-limited 0.2 m/s speed.
  Station gripping-force limit is now 20 N (previously 10 N).
  Left/right Move delivery overlaps when send_arms_parallel is enabled; both
  deliveries finish before send_action returns. Actual clipped targets remain
  the recorded action labels. Per-frame Move messages use DEBUG log level.
  Existing base-frame datasets are not relabeled when switching the default
  recording config to common-world observations; convert them before mixing.
  Hardware delivery test (20 continuous targets per mode): serial mean 4.48 ms,
  p95 8.66 ms; parallel mean 4.22 ms, p95 4.66 ms. These measure RPC dispatch,
  not mechanical travel time. Both empty grippers were left open; no arm motion
  commands were sent. Results: flexiv-local/logs/gripper-delivery-latency-20261024.json.
  A subsequent mechanical test found that continuous 30 Hz Move updates left
  only about 5-8 mm of actual travel for a 25-75 mm oscillating requested width.
  Increasing force alone did not fix it. Reducing updates to about 3 Hz restored
  near-full travel; an initial workaround used a 0.30-second command interval.
  The operator then reported stepping during continuous trigger movement. Further
  A/B tests of the same 0.4 Hz aperture trajectory favored a 0.20-second interval
  and a 0.05 m/s intermediate-speed cap over the 0.30-second/0.2 m/s profile:
  measured aperture range remained about 37 mm for a requested 40 mm range, and
  mean absolute aperture error decreased slightly. This reduces stepping but does
  not turn RDK 1.9's discrete Move interface into a high-bandwidth position servo.
  The next frame after the interval supplies the newest goal; no old-goal queue
  is accumulated. Suppressed frames return the prior delivered target to keep
  dataset actions truthful. Startup/home moves bypass this continuous-input limit.
  Verification with the production limiter restored actual travel to about
  29.7-70.3 mm on both grippers, still with continuous aperture rather than binary
  open/close. This is a command-replanning workaround, not a high-bandwidth servo:
  goal changes can wait up to 0.20 s plus one recording frame before delivery.
  Results: flexiv-local/logs/gripper-force-response-20261024.json,
  flexiv-local/logs/gripper-command-rate-20261024.json, and
  flexiv-local/logs/gripper-rate-limit-verified-20261024.json.
  Smoothness experiments: flexiv-local/logs/gripper-smoothness-speed-probe-20261024.json,
  flexiv-local/logs/gripper-adaptive-smoothness-probe-20261024.json. The final actual
  recording-config test is flexiv-local/logs/gripper-smooth-follow-verified-20261024.json.

  Both station and default recording YAML now select gripper_control_mode:
  force_feedback. Other installations keep the class default "move".
  gripper_aperture.py accepts aperture setpoints synchronously and updates direct
  signed Grasp force from measured aperture on each send_action call. Intermediate
  goals use proportional/damped feedback with limited integral friction
  compensation, capped at 5 N in either direction. Goals near fully closed/open
  use a single Move at 0.2 m/s with the configured 20 N contact-force limit.
  Thus the 20 N setting is retained for full closure, NOT intermediate-aperture
  force feedback. This distinction matters when gripping before full trigger.
  Intermediate goals no longer wait for the former 0.20 s Move limiter.
  Within 0.8 mm of a stationary goal the controller switches to Stop/width hold.
  A separate watchdog requests Stop after 0.25 s without an acknowledged update
  (plus watchdog scheduling and SDK request latency). Reset/manual Move and
  disconnect close feedback and stop its watchdog before proceeding.

  Public action fields stay absolute aperture targets in metres. They are local
  controller setpoints, translated to force internally, rather than raw SDK Move
  targets in this mode. A failed SDK call rejects the action and requests Stop;
  there is no queued/unacknowledged aperture goal. Observations remain actual
  measured width. Use the same controller mode for rollout of these actions.
